## 1. Design Principles

### 1.1 Naming Conventions

- All table names: `snake_case`, plural nouns (`families`, `properties`, `preference_events`)
- All column names: `snake_case`
- Foreign keys: `{referenced_table_singular}_id` (e.g., `family_id`, `property_id`, `suburb_id`)
- Boolean columns: `is_` or `has_` prefix (`is_active`, `has_pool`, `is_deleted`)
- Timestamp columns: `_at` suffix (`created_at`, `updated_at`, `deleted_at`, `evaluated_at`)
- Enum columns: singular noun describing the state (`status`, `type`, `sentiment`)
- Score columns: `_score` suffix, always `NUMERIC(4,2)` (0–10 scale) or `NUMERIC(5,2)` (0–100 scale)
- Confidence columns: `confidence` or `confidence_score`, always `NUMERIC(3,2)` (0.00–1.00)

### 1.2 Primary Key Strategy

All tables use `UUID` primary keys generated by `gen_random_uuid()` (PostgreSQL 13+ built-in, no `uuid-ossp` extension required at PG15).

```sql
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
```

No auto-increment integers as primary keys. UUIDs are used because:
- Safe for distributed inserts (Railway + async workers)
- No information leakage (sequential IDs reveal record counts)
- Consistent across environments (dev/staging/prod)

### 1.3 Timestamp Conventions

Every table has:
```sql
created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
deleted_at  TIMESTAMPTZ          -- NULL = active, set = soft-deleted
```

`updated_at` is maintained by a database trigger applied to all tables (see trigger definition in Section 2.1).

All timestamps stored as `TIMESTAMPTZ` (UTC). Application layer converts to AEST/AEDT for display.

### 1.4 Foreign Key Conventions

All foreign keys use `ON DELETE RESTRICT` by default. Cascade deletes are avoided in favour of application-level soft deletes.

Exception: `evaluation_scores` → `property_evaluations` uses `ON DELETE CASCADE` (scores have no meaning without the parent evaluation).

### 1.5 Row-Level Security (RLS)

Every table containing family data has `family_id UUID NOT NULL` and RLS enabled. The application sets a session variable `app.current_family_id` on connection, and policies restrict all operations to that family.

```sql
-- Pattern applied to all family-scoped tables
ALTER TABLE {table} ENABLE ROW LEVEL SECURITY;
CREATE POLICY family_isolation ON {table}
  USING (family_id = current_setting('app.current_family_id')::UUID);
```

## 2. Complete SQL Schema

### 2.1 Shared Trigger — updated_at Maintenance

```sql
-- Apply this trigger to every table
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Apply per table with:
```sql
CREATE TRIGGER trg_{tablename}_updated_at
  BEFORE UPDATE ON {tablename}
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

```sql
-- ============================================================
-- FAMILIES
-- One record per household. Multi-tenancy anchor table.
-- All user data is isolated by family_id.
-- ============================================================
CREATE TABLE families (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  display_name          TEXT NOT NULL,               -- e.g., "The Altit Family"
  primary_suburb_target TEXT,                        -- e.g., "Gold Coast Southside"
  budget_min_aud        INTEGER,                     -- minimum purchase budget (editable via Family Inputs)
  budget_max_aud        INTEGER,                     -- maximum purchase budget (editable via Family Inputs)
  target_move_date      DATE,                        -- when they want to move (editable via Family Inputs)
  is_active             BOOLEAN NOT NULL DEFAULT TRUE,
  onboarding_completed  BOOLEAN NOT NULL DEFAULT FALSE,
  scoring_model_version TEXT NOT NULL DEFAULT 'v1',  -- track which scoring model version is in use
  -- Configurable scoring weights (editable via Family Inputs > Advanced Settings)
  weight_community      NUMERIC(4,3) NOT NULL DEFAULT 0.250,
  weight_lifestyle      NUMERIC(4,3) NOT NULL DEFAULT 0.200,
  weight_school         NUMERIC(4,3) NOT NULL DEFAULT 0.200,
  weight_property       NUMERIC(4,3) NOT NULL DEFAULT 0.200,
  weight_financial      NUMERIC(4,3) NOT NULL DEFAULT 0.150,
  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at            TIMESTAMPTZ,
  CONSTRAINT weights_sum_to_one CHECK (
    ABS((weight_community + weight_lifestyle + weight_school + weight_property + weight_financial) - 1.0) < 0.001
  )
);

COMMENT ON TABLE families IS 'Primary tenant entity. Every user-generated record references family_id. Does not store a single clerk_user_id — users are linked via family_users table to support multiple accounts per family.';
COMMENT ON COLUMN families.budget_min_aud IS 'Editable at any time via Family Inputs page. Triggers Financial Score recalculation.';
COMMENT ON COLUMN families.scoring_model_version IS 'Version of the scoring model used. Bump when scoring weights change to trigger re-evaluation.';

CREATE TRIGGER trg_families_updated_at
  BEFORE UPDATE ON families
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();


-- ============================================================
-- FAMILY USERS (MULTI-USER AUTH)
-- Links Clerk user accounts to a shared family record.
-- Supports multiple users per family (e.g., Ronnie + Susie).
-- Each user has their own Clerk account and individual
-- preference profile, but shares all family data.
-- ============================================================
CREATE TABLE family_users (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id         UUID NOT NULL REFERENCES families(id) ON DELETE RESTRICT,
  clerk_user_id     TEXT NOT NULL UNIQUE,            -- Clerk auth user ID (unique across all families)
  family_member_id  UUID REFERENCES family_members(id) ON DELETE SET NULL,  -- links to their family member profile
  role              TEXT NOT NULL DEFAULT 'member'
                      CHECK (role IN ('primary', 'member')),
  display_name      TEXT NOT NULL,                   -- display name for this user
  email             TEXT NOT NULL,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at        TIMESTAMPTZ
);

COMMENT ON TABLE family_users IS 'Maps Clerk user IDs to family accounts. Supports multi-user families. One row per user per family. Primary role = account owner/admin.';
COMMENT ON COLUMN family_users.family_member_id IS 'Optional link to the family_members record representing this user in the scoring engine (e.g., Ronnie links to family_member "Ronnie").';
COMMENT ON COLUMN family_users.role IS 'primary: account owner, can manage family settings and invite others. member: can view and interact with all shared family data.';

CREATE INDEX idx_family_users_clerk_user_id ON family_users(clerk_user_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_family_users_family_id ON family_users(family_id) WHERE deleted_at IS NULL;

CREATE TRIGGER trg_family_users_updated_at
  BEFORE UPDATE ON family_users
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- FAMILY INVITES
-- Pending email invitations for additional family members.
-- Primary user sends invite → invitee clicks link → 
-- signs up via Clerk → accepted, creates family_users record.
-- ============================================================
CREATE TABLE family_invites (

                      CHECK (role IN ('primary', 'member')),

                      CHECK (status IN ('pending', 'accepted', 'expired', 'revoked')),
  expires_at        TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '7 days',
  accepted_at       TIMESTAMPTZ,
  accepted_by_user_id UUID REFERENCES family_users(id) ON DELETE SET NULL,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE family_invites IS 'Pending invitations for additional family members. Token is emailed to invitee and validated when they sign up.';
COMMENT ON COLUMN family_invites.invite_token IS 'Cryptographically secure random token (32 bytes, URL-safe base64). Embedded in invite URL: /invite/accept?token={invite_token}';

CREATE INDEX idx_family_invites_token ON family_invites(invite_token) WHERE status = 'pending';
CREATE INDEX idx_family_invites_email ON family_invites(email, status);

  BEFORE UPDATE ON family_members

-- ============================================================
-- FAMILY PREFERENCES (LEARNED WEIGHTS)
-- The AI's current best understanding of what this family values.
-- One row per family per attribute. Updated by preference learning pipeline.
-- ============================================================
CREATE TABLE family_preferences (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id           UUID NOT NULL REFERENCES families(id) ON DELETE RESTRICT,
  attribute           TEXT NOT NULL,               -- e.g., 'ModernCoastalDesign', 'PoolRequired', 'BurleighAccess'
  category            TEXT NOT NULL,               -- 'community', 'lifestyle', 'school', 'property', 'financial'
  current_weight      NUMERIC(3,1) NOT NULL DEFAULT 2.5 CHECK (current_weight >= 0 AND current_weight <= 5),
  confidence          NUMERIC(3,2) NOT NULL DEFAULT 0.0 CHECK (confidence >= 0 AND confidence <= 1),
  status              TEXT NOT NULL DEFAULT 'Emerging'
                        CHECK (status IN ('Emerging', 'Confirmed', 'Contradicted', 'Retired', 'Manual')),
  positive_signal_count INTEGER NOT NULL DEFAULT 0,
  negative_signal_count INTEGER NOT NULL DEFAULT 0,
  last_signal_at      TIMESTAMPTZ,               -- when the most recent preference event was received
  is_deal_breaker     BOOLEAN NOT NULL DEFAULT FALSE,
  deal_breaker_set_at TIMESTAMPTZ,               -- when this was elevated to deal-breaker status
  notes               TEXT,                      -- optional human annotation
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at          TIMESTAMPTZ,
  UNIQUE (family_id, attribute)                  -- one row per attribute per family
);

COMMENT ON TABLE family_preferences IS 'Learned preference weights per attribute. Single source of truth for what the family cares about. Maintained by preference learning pipeline.';
COMMENT ON COLUMN family_preferences.attribute IS 'Attribute identifier. Must match vocabulary used in preference_events and property feature extraction.';
COMMENT ON COLUMN family_preferences.current_weight IS '0=strongly dislike, 2.5=neutral, 5=essential.';

CREATE TRIGGER trg_family_preferences_updated_at
  BEFORE UPDATE ON family_preferences
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

ALTER TABLE family_preferences ENABLE ROW LEVEL SECURITY;
CREATE POLICY family_isolation ON family_preferences
  USING (family_id = current_setting('app.current_family_id', TRUE)::UUID);


-- ============================================================
-- FAMILY MEMORY
-- The AI advisor's persistent memory about this family.
-- Structured memory store, not raw conversation logs.
-- ============================================================
CREATE TABLE family_memory (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id     UUID NOT NULL REFERENCES families(id) ON DELETE RESTRICT,
  member_id     UUID REFERENCES family_members(id),  -- NULL = applies to whole family
  memory_type   TEXT NOT NULL CHECK (memory_type IN ('Permanent', 'Preference', 'Learned', 'Session', 'Decision')),
  attribute     TEXT,                               -- NULL for general memories
  content       TEXT NOT NULL,                     -- natural language memory content
  structured    JSONB,                             -- optional structured data supporting the memory
  source        TEXT,                             -- where this memory came from
  confidence    NUMERIC(3,2) NOT NULL DEFAULT 1.0 CHECK (confidence >= 0 AND confidence <= 1),
  expires_at    TIMESTAMPTZ,                      -- for Session memories, when they expire
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at    TIMESTAMPTZ
);

COMMENT ON TABLE family_memory IS 'Persistent AI advisor memory. Permanent memories never expire. Session memories expire within 24h. Learned memories are managed by consolidation pipeline.';
COMMENT ON COLUMN family_memory.structured IS 'Optional machine-readable data. e.g., {"attribute": "PoolRequired", "weight": 4.5}';

CREATE TRIGGER trg_family_memory_updated_at
  BEFORE UPDATE ON family_memory
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

ALTER TABLE family_memory ENABLE ROW LEVEL SECURITY;
CREATE POLICY family_isolation ON family_memory
  USING (family_id = current_setting('app.current_family_id', TRUE)::UUID);


-- ============================================================
-- MEMORY EVENTS
-- Audit trail of all changes to family memory and preferences.
-- Append-only. Never updated or deleted.
-- ============================================================
CREATE TABLE memory_events (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id       UUID NOT NULL REFERENCES families(id) ON DELETE RESTRICT,
  memory_id       UUID REFERENCES family_memory(id),
  preference_id   UUID REFERENCES family_preferences(id),
  event_type      TEXT NOT NULL CHECK (event_type IN (
                    'memory_created', 'memory_updated', 'memory_expired',
                    'preference_updated', 'preference_retired', 'contradiction_detected',
                    'deal_breaker_set', 'deal_breaker_cleared', 'manual_override')),
  attribute       TEXT,
  old_value       JSONB,                           -- state before change
  new_value       JSONB,                           -- state after change
  triggered_by    TEXT,                            -- 'preference_pipeline', 'consolidation', 'user', 'ai'
  notes           TEXT,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
  -- No updated_at or deleted_at — append-only audit table
);

COMMENT ON TABLE memory_events IS 'Immutable audit trail of all memory and preference changes. Never modify or delete rows.';

ALTER TABLE memory_events ENABLE ROW LEVEL SECURITY;
CREATE POLICY family_isolation ON memory_events
  USING (family_id = current_setting('app.current_family_id', TRUE)::UUID);
```

### 2.3 Property Domain

```sql
-- ============================================================
-- PROPERTIES
-- Core property records. One row per unique property address.
-- A family can save multiple properties; family_id scopes the record.
-- ============================================================
CREATE TABLE properties (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id             UUID NOT NULL REFERENCES families(id) ON DELETE RESTRICT,
  suburb_id             UUID REFERENCES suburbs(id),  -- populated after suburb lookup
  source_url            TEXT,                        -- original listing URL (REA/Domain)
  source_platform       TEXT CHECK (source_platform IN ('realestate', 'domain', 'manual', 'agent')),
  source_listing_id     TEXT,                        -- REA/Domain internal listing ID

  -- Address
  address_street        TEXT NOT NULL,
  address_suburb        TEXT NOT NULL,
  address_state         TEXT NOT NULL DEFAULT 'QLD',
  address_postcode      CHAR(4) NOT NULL,
  latitude              NUMERIC(9,6),
  longitude             NUMERIC(9,6),

  -- Core property facts
  property_type         TEXT NOT NULL CHECK (property_type IN ('house', 'townhouse', 'unit', 'acreage', 'other')),
  bedrooms              INTEGER CHECK (bedrooms >= 0 AND bedrooms <= 20),
  bathrooms             NUMERIC(3,1) CHECK (bathrooms >= 0 AND bathrooms <= 20),
  car_spaces            INTEGER CHECK (car_spaces >= 0 AND car_spaces <= 20),
  land_area_sqm         INTEGER CHECK (land_area_sqm > 0),
  house_area_sqm        INTEGER CHECK (house_area_sqm > 0),

  -- Price
  listing_price_aud     INTEGER,                    -- exact price if known
  price_range_low_aud   INTEGER,                    -- if listed as range
  price_range_high_aud  INTEGER,
  price_is_range        BOOLEAN NOT NULL DEFAULT FALSE,

  -- Listing text
  description_text      TEXT,
  description_tsvector  TSVECTOR                   -- full-text search vector (populated by trigger)
                        GENERATED ALWAYS AS (to_tsvector('english', COALESCE(description_text, ''))) STORED,

  -- Flood and risk
  flood_risk_category   TEXT DEFAULT 'unknown'
                        CHECK (flood_risk_category IN ('high', 'medium', 'low', 'none', 'unknown')),
  flood_risk_source_date DATE,

  -- Agent
  agent_name            TEXT,
  agency_name           TEXT,

  -- Data quality
  data_quality_score    INTEGER NOT NULL DEFAULT 50 CHECK (data_quality_score >= 0 AND data_quality_score <= 100),
  extraction_confidence NUMERIC(3,2),               -- OpenAI extraction confidence

  -- Status lifecycle
  status                TEXT NOT NULL DEFAULT 'saved'
                        CHECK (status IN ('saved', 'shortlisted', 'inspecting', 'offer', 'rejected', 'sold', 'withdrawn')),
  is_favourite          BOOLEAN NOT NULL DEFAULT FALSE,
  family_notes          TEXT,                      -- free-form family note on the property

  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at            TIMESTAMPTZ
);

COMMENT ON TABLE properties IS 'Core property records. Scoped to family. source_url is the listing URL pasted by user.';
COMMENT ON COLUMN properties.description_tsvector IS 'Auto-generated full-text search vector from description_text. Used for search queries.';
COMMENT ON COLUMN properties.status IS 'Lifecycle status. rejected and sold properties remain for audit but excluded from recommendations.';

CREATE TRIGGER trg_properties_updated_at
  BEFORE UPDATE ON properties
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

ALTER TABLE properties ENABLE ROW LEVEL SECURITY;
CREATE POLICY family_isolation ON properties
  USING (family_id = current_setting('app.current_family_id', TRUE)::UUID);
```

### 2.4 Location Domain

```sql
-- ============================================================
-- SUBURBS
-- Reference table for all Gold Coast suburbs.
-- Pre-seeded before launch. Shared across all families (no family_id).
-- ============================================================
CREATE TABLE suburbs (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name                  TEXT NOT NULL UNIQUE,      -- e.g., 'Burleigh Heads'
  postcode              CHAR(4) NOT NULL,
  state                 CHAR(3) NOT NULL DEFAULT 'QLD',
  lga                   TEXT DEFAULT 'Gold Coast City Council',
  latitude              NUMERIC(9,6) NOT NULL,     -- suburb centroid
  longitude             NUMERIC(9,6) NOT NULL,
  bounding_box          JSONB,                     -- {north, south, east, west} for POI queries
  tier                  CHAR(1) CHECK (tier IN ('A', 'B', 'C')),
  is_active             BOOLEAN NOT NULL DEFAULT TRUE,  -- exclude from queries if false
  abs_sa2_code          TEXT,                      -- ABS Statistical Area 2 code for Census matching
  police_division       TEXT,                      -- QPS division name for crime data mapping
  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE suburbs IS 'Reference table for Gold Coast suburbs. Pre-seeded. No soft delete — deactivate with is_active=false.';
COMMENT ON COLUMN suburbs.tier IS 'A=premium coastal, B=family/canal, C=growth/hinterland. Used for default scoring baselines.';

CREATE TRIGGER trg_suburbs_updated_at
  BEFORE UPDATE ON suburbs
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();


-- ============================================================
-- SUBURB METRICS
-- One row per suburb, holding all calculated metric values.
-- Updated by quarterly ETL pipeline.
-- ============================================================
CREATE TABLE suburb_metrics (
  id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  suburb_id                   UUID NOT NULL UNIQUE REFERENCES suburbs(id),

  -- Community sub-scores (0–10)
  owner_occupier_rate         NUMERIC(5,2),        -- % of dwellings owner-occupied
  owner_occupier_score        NUMERIC(4,2),
  family_density_pct          NUMERIC(5,2),        -- % households with children under 15
  family_density_score        NUMERIC(4,2),
  educational_attainment_pct  NUMERIC(5,2),        -- % adults with bachelor+ degree
  educational_attainment_score NUMERIC(4,2),
  median_weekly_household_income_aud INTEGER,
  median_income_score         NUMERIC(4,2),
  crime_index                 NUMERIC(6,2),        -- offences per 1000 population (lower is better)
  crime_score                 NUMERIC(4,2),        -- inverted for scoring (high crime = low score)
  community_engagement_score  NUMERIC(4,2),        -- composite of volunteering, community orgs, sporting clubs
  community_score             NUMERIC(4,2),        -- composite community score

  -- Data provenance
  abs_data_year               INTEGER DEFAULT 2021,
  crime_data_quarter          TEXT,                -- e.g., '2025-Q3'
  last_refreshed_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  created_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE suburb_metrics IS 'Calculated metric values for community scoring. One row per suburb. Updated by quarterly ETL.';

CREATE TRIGGER trg_suburb_metrics_updated_at
  BEFORE UPDATE ON suburb_metrics
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- SUBURB LIFESTYLE ASSETS

-- ============================================================
CREATE TABLE suburb_lifestyle_assets (
  id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  suburb_id                   UUID NOT NULL UNIQUE REFERENCES suburbs(id),

  -- POI counts (sourced from Google Places + OSM)
  cafe_restaurant_count       INTEGER DEFAULT 0,
  gym_fitness_count           INTEGER DEFAULT 0,
  pilates_yoga_count          INTEGER DEFAULT 0,
  park_reserve_count          INTEGER DEFAULT 0,
  shopping_centre_count       INTEGER DEFAULT 0,
  medical_gp_count            INTEGER DEFAULT 0,
```

## 6. Common Query Patterns

```sql
-- ============================================================
-- QUERY 1: All properties for a family with current evaluation scores
-- Used for: property list view, dashboard
-- ============================================================
SELECT
  p.id,
  p.address_street,
  p.address_suburb,
  p.listing_price_aud,
  p.bedrooms,
  p.bathrooms,
  p.land_area_sqm,
  p.property_type,
  p.status,
  p.is_favourite,
  p.data_quality_score,
  s.name AS suburb_name,
  s.tier AS suburb_tier,
  es.family_fit_score,
  es.five_year_fit_score,
  es.community_score,
  es.lifestyle_score,
  es.school_score,
  es.property_score,
  es.financial_score,
  pe.confidence_score,
  pe.executive_summary,
  r.rank_position
FROM properties p
LEFT JOIN suburbs s ON s.id = p.suburb_id
LEFT JOIN property_evaluations pe
  ON pe.property_id = p.id
  AND pe.family_id = p.family_id
  AND pe.is_current = TRUE
  AND pe.deleted_at IS NULL
LEFT JOIN evaluation_scores es ON es.evaluation_id = pe.id
LEFT JOIN recommendations r
  ON r.property_id = p.id
  AND r.family_id = p.family_id
  AND r.status = 'active'
WHERE p.family_id = :family_id
  AND p.deleted_at IS NULL
  AND p.status NOT IN ('rejected', 'sold', 'withdrawn')
ORDER BY r.rank_position ASC NULLS LAST, p.created_at DESC;


-- ============================================================
-- QUERY 2: Shortlisted properties for a family
-- ============================================================
SELECT
  p.id,
  p.address_street,
  p.address_suburb,
  p.listing_price_aud,
  p.status,
  es.family_fit_score,
  es.five_year_fit_score,
  pe.executive_summary,
  r.rank_position,
  r.headline
FROM properties p
JOIN property_evaluations pe
  ON pe.property_id = p.id AND pe.family_id = p.family_id AND pe.is_current = TRUE
JOIN evaluation_scores es ON es.evaluation_id = pe.id
LEFT JOIN recommendations r ON r.property_id = p.id AND r.family_id = p.family_id
WHERE p.family_id = :family_id
  AND p.status = 'shortlisted'
  AND p.deleted_at IS NULL
ORDER BY es.family_fit_score DESC;


-- ============================================================
-- QUERY 3: Top recommendations for a family (ordered by fit score)
-- Used for: recommendations panel
-- ============================================================
SELECT
  r.rank_position,
  r.headline,
  r.summary,
  r.family_fit_score,
  r.score_delta,
  p.id AS property_id,
  p.address_street,
  p.address_suburb,
  p.listing_price_aud,
  p.bedrooms,
  p.bathrooms,
  s.name AS suburb_name,
  s.tier,
  es.community_score,
  es.lifestyle_score,
  es.school_score,
  es.property_score
FROM recommendations r
JOIN properties p ON p.id = r.property_id
JOIN property_evaluations pe ON pe.id = r.evaluation_id
JOIN evaluation_scores es ON es.evaluation_id = pe.id
JOIN suburbs s ON s.id = p.suburb_id
WHERE r.family_id = :family_id
  AND r.status = 'active'
  AND p.deleted_at IS NULL
ORDER BY r.rank_position ASC NULLS LAST
LIMIT 10;


-- ============================================================
-- QUERY 4: Preference events for a family filtered by attribute
-- Used for: preference learning pipeline, preference detail view
-- ============================================================
SELECT
  pe.id,
  pe.attribute,
  pe.sentiment,
  pe.strength,
  pe.source,
  pe.context_text,
  pe.created_at,
  fm.first_name AS member_name,
  p.address_street AS property_address
FROM preference_events pe
LEFT JOIN family_members fm ON fm.id = pe.member_id
LEFT JOIN properties p ON p.id = pe.property_id
WHERE pe.family_id = :family_id
  AND pe.attribute = :attribute
ORDER BY pe.created_at DESC;

-- Aggregated version for preference weight calculation:
SELECT
  attribute,
  COUNT(*) FILTER (WHERE sentiment = 'Positive') AS positive_count,
  COUNT(*) FILTER (WHERE sentiment IN ('Negative', 'DealBreaker')) AS negative_count,
  AVG(strength) AS avg_strength,
  MAX(created_at) AS last_signal_at
FROM preference_events
WHERE family_id = :family_id
  AND created_at > NOW() - INTERVAL '90 days'
GROUP BY attribute;


-- ============================================================
-- QUERY 5: Family memory by type
-- Used for: AI advisor context loading
-- ============================================================
SELECT
  fm.id,
  fm.memory_type,
  fm.attribute,
  fm.content,
  fm.structured,
  fm.confidence,
  fm.source,
  fmem.first_name AS member_name
FROM family_memory fm
LEFT JOIN family_members fmem ON fmem.id = fm.member_id
WHERE fm.family_id = :family_id
  AND fm.memory_type = :memory_type
  AND fm.deleted_at IS NULL
  AND (fm.expires_at IS NULL OR fm.expires_at > NOW())
ORDER BY fm.confidence DESC, fm.updated_at DESC;


-- ============================================================
-- QUERY 6: Decision journal with related property and suburb
-- Used for: journal view, AI context
-- ============================================================
SELECT
  dj.id,
  dj.entry_type,
  dj.title,
  dj.body,
  dj.mood,
  dj.tags,
  dj.is_pinned,
  dj.created_at,
  p.address_street AS property_address,
  p.address_suburb AS property_suburb,
  s.name AS suburb_name,
  -- Aggregate member impacts as JSON array
  COALESCE(
    JSON_AGG(
      JSON_BUILD_OBJECT(
        'member_name', fm.first_name,
        'impact_note', djmi.impact_note,
        'sentiment', djmi.sentiment
      )
    ) FILTER (WHERE fm.id IS NOT NULL),
    '[]'
  ) AS member_impacts
FROM decision_journal_entries dj
LEFT JOIN properties p ON p.id = dj.property_id
LEFT JOIN suburbs s ON s.id = dj.suburb_id
LEFT JOIN decision_journal_member_impacts djmi ON djmi.entry_id = dj.id
LEFT JOIN family_members fm ON fm.id = djmi.member_id
WHERE dj.family_id = :family_id
  AND dj.deleted_at IS NULL
GROUP BY dj.id, p.address_street, p.address_suburb, s.name
ORDER BY dj.is_pinned DESC, dj.created_at DESC;


-- ============================================================
-- QUERY 7: Full evaluation detail (single property)
-- Used for: property detail / evaluation card
-- ============================================================
SELECT
  pe.id AS evaluation_id,
  pe.evaluated_at,
  pe.confidence_score,
  pe.executive_summary,
  pe.community_narrative,
  pe.lifestyle_narrative,
  pe.school_narrative,
  pe.property_narrative,
  pe.financial_narrative,
  pe.five_year_narrative,
  pe.deal_breakers_flagged,
  es.*,
  -- Per-member commentary as JSON array
  COALESCE(
    JSON_AGG(
      JSON_BUILD_OBJECT(
        'member_id', epm.member_id,
        'member_name', fm.first_name,
        'commentary', epm.commentary,
        'key_positives', epm.key_positives,
        'key_concerns', epm.key_concerns,
        'fit_score', epm.fit_score
      )
    ) FILTER (WHERE epm.id IS NOT NULL),
    '[]'
  ) AS per_member_commentary
FROM property_evaluations pe
JOIN evaluation_scores es ON es.evaluation_id = pe.id
LEFT JOIN evaluation_per_member epm ON epm.evaluation_id = pe.id
LEFT JOIN family_members fm ON fm.id = epm.member_id
WHERE pe.family_id = :family_id
  AND pe.property_id = :property_id
  AND pe.is_current = TRUE
  AND pe.deleted_at IS NULL
GROUP BY pe.id, es.id;
```

## 7. Full-Text Search

### 7.1 Implementation

Full-text search is implemented using PostgreSQL's built-in `tsvector` and `tsquery` types. No external search engine (Elasticsearch, Typesense) is needed at MVP scale.

**Indexed columns**:
- `properties.description_tsvector` — property listing descriptions
- `decision_journal_entries.body_tsvector` — journal entry content

Both are `GENERATED ALWAYS AS ... STORED` columns, meaning they are automatically maintained by PostgreSQL on insert/update.

### 7.2 Search Queries

```sql
-- Search property descriptions across a family's properties
SELECT
  p.id,
  p.address_street,
  p.address_suburb,
  p.listing_price_aud,
  ts_rank(p.description_tsvector, query) AS relevance,
  ts_headline('english', p.description_text, query,
    'StartSel=<mark>, StopSel=</mark>, MaxWords=35, MinWords=15') AS excerpt
FROM properties p,
     to_tsquery('english', :search_terms) AS query
WHERE p.family_id = :family_id
  AND p.deleted_at IS NULL
  AND p.description_tsvector @@ query
ORDER BY relevance DESC;

-- Search decision journal entries
SELECT
  dj.id,
  dj.title,
  dj.entry_type,
  dj.created_at,
  ts_rank(dj.body_tsvector, query) AS relevance,
  ts_headline('english', dj.body, query,
    'StartSel=<mark>, StopSel=</mark>, MaxWords=40, MinWords=20') AS excerpt
FROM decision_journal_entries dj,
     to_tsquery('english', :search_terms) AS query
WHERE dj.family_id = :family_id
  AND dj.deleted_at IS NULL
  AND dj.body_tsvector @@ query
ORDER BY relevance DESC;
```

### 7.3 User-Facing Search Input Handling

User search input must be sanitised before passing to `to_tsquery`. Use `plainto_tsquery` for simple user input (handles spaces, ignores operators):

```sql
-- Safe for raw user input (no need to escape operators)
SELECT ... WHERE description_tsvector @@ plainto_tsquery('english', :user_input)

-- For advanced search (supports AND, OR, NOT with : syntax)
SELECT ... WHERE description_tsvector @@ websearch_to_tsquery('english', :user_input)
```

### 7.4 Search Index

The GIN indexes on both tsvector columns (defined in Section 3) provide fast full-text lookups. GIN is preferred over GiST for static or infrequently updated text content because it has faster lookups at the cost of slightly slower updates — acceptable for property descriptions.
